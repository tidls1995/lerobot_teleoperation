# 배포 — 원격 사용자에게 무엇을 주고, 받은 사람은 무엇을 하나

원격 사용자는 파이썬을 설치하지 않는다. `so101-teleop.exe` 하나로 진단부터 조종까지
한다. 캘리브레이션은 **서보 안에** 들어 있으므로 파일을 함께 줄 필요가 없다.

## 주는 것

| | 무엇 | 비고 |
|---|---|---|
| 물건 | 리더 암 2대 (좌·우) + 전원 어댑터 + USB 케이블 | **캘리브레이션이 끝난 팔이어야 한다** |
| 파일 | `so101-teleop.exe` | `python -m tools.build_exe` 로 만든다 |
| 파일 | `home.yaml` | exe 와 **같은 폴더**에 둔다 |

`home.yaml` 을 빼고 줘도 된다. exe 가 처음 실행될 때 본보기를 만들고 무엇을 채우라고
알려준다. 다만 그러면 사용자가 시리얼 번호를 직접 확인해야 하므로, **팔을 보낸 사람이
미리 채워서 주는 편이 낫다.**

### `home.yaml` 에서 사람마다 다른 값

```yaml
server_host: "..."        # 작업대 PC 주소
arms:
  left:  { serial_number: "...", calibration_id: "leader_left" }
  right: { serial_number: "...", calibration_id: "leader_right" }
```

`serial_number` 는 **팔에 달린 USB 어댑터의 번호**다. 팔을 따라다니므로 그 사람이
어느 PC 를 쓰든 그대로 맞다. 번호는 팔을 꽂고 exe 메뉴 **4번**으로 확인한다.

`calibration_id` 는 이 프로그램에서 쓰이지 않는다 (캘리브레이션은 서보 안에 있다).
어느 팔인지 적어두는 이름으로만 남아 있다.

## 받은 사람이 하는 일

1. 팔 2대에 전원을 꽂고 USB 를 PC 에 연결한다.
2. `so101-teleop.exe` 를 실행한다.
3. **1번 — 내 팔 확인.** 모터 12개가 다 `yes` 여야 한다.
4. **2번 — 회선 확인.** 제어와 영상이 모두 OK 여야 한다.
5. **3번 — 조종.** 창이 뜬다. 스페이스로 클러치, R 로 리셋, ESC 로 종료.

메뉴 순서가 곧 문제 해결 순서다. 위에서 막히면 아래는 볼 것도 없다. "안 움직여요"
라는 연락이 오면 **몇 번에서 막혔는지**부터 묻는다.

## 걸리는 것 세 가지 (미리 말해 둘 것)

### 1. Windows SmartScreen

서명하지 않은 exe 라 처음 실행할 때 "Windows의 PC 보호" 창이 뜬다. **추가 정보 →
실행**을 눌러야 한다. 미리 말해 두지 않으면 바이러스로 알고 지운다.

메일이나 웹으로 받은 파일은 차단 표시가 붙기도 한다. 그때는 파일 우클릭 → 속성 →
아래쪽 **차단 해제** 체크.

> 코드 서명 인증서를 사면 없앨 수 있지만 유료이고, 배포처가 3명뿐이라 지금은
> 안내로 대신한다.

### 2. CH343 USB 드라이버

팔의 USB 어댑터 드라이버다. Windows 가 자동으로 잡는 경우가 많지만, 안 잡히면 **COM
포트가 아예 나타나지 않는다.** 증상은 메뉴 4번이 빈 목록을 보여주는 것이다. 한 번
설치하면 그 PC 에서는 끝이다.

### 3. 주소가 사설 IP 이면 집에서는 안 된다

`192.168.x.x` 는 같은 공유기 안에서만 통한다. 사무실 Wi-Fi 안의 다른 노트북에서는
그대로 되지만, 집에 들고 가면 닿지 않는다. 인터넷을 건너가려면 작업대 쪽에
**포트포워딩과 공인 IP** 가 필요하다 (4단계).

> **공인 IP 를 저장소에 커밋하지 않는다.** 저장소는 공개이고 프로토콜은 전부 문서에
> 있으며 서버에는 인증이 없다. 주소가 곧 로봇의 열쇠다. 그래서 `home.yaml` 은 exe
> 옆에 두는 파일이고, 본보기에는 `CHANGE-ME` 만 들어 있다.

## 팔을 옮기거나 새로 살 때

**쓰던 팔 → 새 PC:** 그냥 된다. 캘리브레이션이 서보 안에 있고, 시리얼 번호는 팔을
따라간다. exe 와 `home.yaml` 만 복사하면 끝이다 (드라이버는 위 2번).

**새로 산 팔:** 한 번은 준비가 필요하다. 공장 상태의 서보는

- 모터 ID 가 전부 1번이라 하나씩 1~6 으로 지정해야 하고,
- 캘리브레이션이 없다 (범위 0~4095, 영점 0).

exe 는 **읽기만** 하므로 이 준비를 못 한다. lerobot 이 설치된 PC 에서 한 번 해야 하고,
그 다음부터는 어느 PC 로든 들고 다닐 수 있다. exe 메뉴 1번이 이 상태를
`never calibrated` 로 잡아준다.

## exe 만들기

```bash
python -m tools.build_exe
```

PyInstaller 를 직접 부르지 않는다. 두 가지 방식으로 조용히 속기 때문이다.

- **exe 가 실행 중이면 덮어쓰기가 막힌다.** PyInstaller 는 그것을 stderr 로만 뱉으므로
  성공한 줄 알고 **옛 exe 를 계속 테스트하게 된다** (실측: 그렇게 10분을 날렸다).
- **빌드가 끝나는 것과 도는 것은 다르다.** 제외 목록을 잘못 잡으면 빌드는 멀쩡히
  끝나고 실행할 때 죽는다 (실측: `libexpat.dll`, `jaraco` 로 두 번).

`tools/build_exe.py` 는 실행 중인지 확인하고, 파일이 정말 바뀌었는지 보고, 빈 폴더에서
띄워 본다. 그래도 **스모크는 시작만 증명한다** — 메뉴 3번(창을 띄우고 영상을 푸는 것)은
사람이 한 번 눌러 봐야 한다.

## 크기와 그 이유

66.5 MB 단일 파일이다. `lerobot` 을 쓰면 `torch` 4.2GB 가 딸려와 배포가 불가능해지므로,
클라이언트는 `scservo_sdk`(0.1MB)로 서보와 직접 말한다. 숫자가 lerobot 과 같다는 것은
`tools/compare_read.py` 로 실물에서 확인했다 (관절 12개 전부 차이 0.000).

`tests/test_build.py` 가 클라이언트를 import 했을 때 `lerobot`/`torch`/`pandas` 가
딸려오지 않는지 검사한다. 실수로 다시 import 되면 exe 가 몇 GB 로 부푸는데, 그때는
이미 늦고 무엇이 끌고 왔는지 찾기도 어렵다.
